DEX Aggregator (42 Chain / QL1 / Testnet)

Finds the route that gives you the most, across every pool.

A "route" is the path a swap takes. For example, USDT → 42 can go directly, or via another token like USDT → FISH → 42, and which one gives more depends on the amount. This site quotes every path — including "splits" that divide your amount across several routes — and ranks them, the same idea as 1inch.

Cross-chain swap (QL1 <-> 42 Chain)

Swap into a token on the other chain. The flow has 4 steps — swap, bridge send, wait for arrival, final swap — and you confirm (sign) each step yourself. Nothing is sent automatically. Progress is saved in this browser, so you can close the page and resume.

Only tokens with verified bridge deliveries can be used as the bridge token (QOM / BABY / CAW / FATHER / HAWK / KET / O / OSAK — except OSAK from 42 Chain to QL1, where no sends could be verified). Any token with a working bridge connection can be used as the bridge token — the mechanism does not differ per token. For each bridge token, the combinations of swap paths (full routes) are all listed, so you can see why a longer route pays more and what a simpler route would pay, and choose for yourself. Splits across full routes are quoted too, and a split plan card is shown only when a split actually beats the best single route (each part bridges separately, so the 42 Chain messaging cost is charged once per part). The bridge fee is 0. Sending from 42 Chain also costs a messaging fee (approx. 2.94 [42], re-fetched at send time); sending from QL1 measured 0. Arrival can take several minutes (one measured case took about 5 minutes).

Price gaps (arbitrage)

When the same token is priced differently on QL1 and 42 Chain, you can capture the difference by buying it where it is cheap, bridging it, and selling it where it is expensive (arbitrage — trading is also what closes such gaps). This board computes routes that start and end in QOM, the common currency, for every bridgeable token in both directions using real route quotes (getAmountsOut on each leg) — spot-price comparisons would lie on these thin pools, so they are not used.

Not available on the testnet (no QL1 testnet bridge is known). Select a mainnet chain.

About sizes: a bridge send from 42 Chain carries a fixed messaging fee (approx. 2.94 [42], about 3.45B in QOM terms), so at 1B QOM or below every 42 Chain-origin route is negative from that fee alone. The default 100B QOM keeps the fee at about 3.5%. Much larger sizes drown in price impact on these thin pools instead. Small sizes can still reveal small QL1-origin gaps (that direction's messaging fee is 0).

  • Quotes use current pool prices. Prices can move during the bridge trip (several minutes), and the result will change with them.
  • Price gaps shrink and disappear as people trade them (that is how arbitrage works). A gap shown here is not guaranteed to still be there when you execute.
  • Round trips are riskier than one-way routes (two bridge trips, twice as long for prices to move).
  • Net figures deduct the bridge messaging fee converted into QOM, but not DEX gas (gas figures are estimates).
  • Routes whose purchasable amount is below the bridge minimum (1 token) are shown as "cannot quote" (e.g. KET at small sizes).

How it works — and honest limits

  • Quotes are real: the site calls the DEX router's getAmountsOut for every candidate route (direct, 1 hop, 2 hops). Nothing is guessed from a price feed.
  • Splits across the top routes (90/10, 80/20, …, 50/50, and 3-way splits) are quoted the same way. When a split beats every single route, it is shown as the recommended "Split plan".
  • Executing a split needs a dedicated aggregator contract. The contract (SplitSwap) is published in this site's repository, and you can deploy it yourself from your own wallet right on this page, per chain (v7). The deployed address is saved in this browser, and split plans then execute as shown. On a chain where you have not deployed it, a split is a quote only and execution uses a single route. The testnet works the same way but needs TEST42 for gas (no public faucet was found). Each split leg also carries its own minimum output (v7). Cross-chain split plans are shown only when they still beat the best single route after the extra bridge messaging cost (v6.5).
  • The testnet DEX router address in public records had one character too many; this site uses the address recovered by verifying every candidate live on-chain. The testnet token list is built from the testnet's real pairs.
  • "Price impact" is the difference between a no-fee estimate from pool reserves and the real quote (fees + size impact). Gas figures are estimates too.
  • Small pools can move between quote and execution. Try a small amount first before swapping a large one.
  • This site takes no fee. Swaps talk directly to each chain's DEX router (42 Chain: Don't Panic / QL1: QomSwap).
  • Full routes (v5): cross-chain results are listed as full routes — one bundled "swap 1 -> bridge -> swap 2" each. For every bridge token, the top path variants of both swaps are combined, so simpler routes (fewer pools) and longer-but-better routes are both visible and selectable. Starting a route stores its exact paths, and steps 1 and 4 execute along those stored paths (re-quoting that path at execution time; if it no longer works, the flow stops instead of switching to another path).
  • Cross-chain splits (v6-v6.4): splits across full routes are evaluated by actually re-quoting each part along its own route at its own amount. Candidates are the top full routes by final output, and different paths through the same bridge token (e.g. USDT -> FISH -> QOM) count as separate candidates. Allocations are searched coarsely in 10% steps (2-5 parts), pairs are brute-forced in 1% steps, and the best allocation is then refined in 1% steps (the refinement may add any route from the full route list). Parts that share the same bridge token and the same second swap are quoted as ONE combined second swap on their summed arrival, split back pro-rata, so using the same pool twice never inflates the total (v6.4). A "Split plan" card appears only when a split beats the best single full route; starting it runs a per-part guided flow (swap -> bridge -> arrival watch -> swap, part by part). Each part bridges separately, so a 42 Chain origin pays the messaging cost once per part (the total is shown on the card). When a split loses, no plan is offered and the site honestly says a single route is best. Measured contrast: at 1,000 USDT -> QOM on QL1 a split paid +44.5% over the best single route, and at 1,000 USDT -> qCAW on QL1 a split using both paths through the QOM bridge token paid +48.8%.
  • Price-gap display (v4): cross-chain quotes now show a benchmark — the "obvious" route (via QOM, or bridging the token you pay itself when possible) — and each candidate's difference from it. When the best candidate beats the benchmark by more than 0.5%, it gets a "Price gap +x%" badge (measured example: 100 [42] on 42 Chain -> QOM on QL1, the BABY bridge route paid +6.33% more than the QOM benchmark; at 500 [42] the BABY pools cannot absorb the size and it flips to −25.8% — always re-quote at your own size).
  • Cross-chain (v3): bridging uses Hyperlane (Zaphod Bridge). A direction/token is enabled only where delivery was proven on-chain: message IDs were taken from real send transactions and checked against the destination chain's mailbox delivered() (sampled 2026-11-06: QL1 -> 42 Chain 16/16 across all 8 tokens; 42 Chain -> QL1 13/13 across 7 tokens, excluding OSAK, whose 42 Chain router has no sends at all in its history, so that one direction is disabled). The bridge site's own stats showing "0 QL1-origin deliveries" are an indexer gap — deliveries are confirmed on-chain. The final swap executes at arrival-time prices, so the final figure is an estimate.
